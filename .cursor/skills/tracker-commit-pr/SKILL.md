# Коммиты и PR после ревью бота

Связка с `tracker-task`: сначала реализация и проверка в браузере, затем этот навык.

Ключ задачи и тип бери из **текущей ветки** `feat/DENT-241`, `issue/DENT-284`, `fix/STO-170`. Если ветка не по шаблону — спроси.

## Формат коммита

Тип в сообщении коммита **не обязан** совпадать с именем ветки один в один: для ветки `issue/…` в коммите используй `fix`, не `issue`.

| Префикс ветки | Тип в коммите |
|---------------|----------------|
| `feat`        | `feat`         |
| `issue`       | `fix`          |
| `fix`         | `fix`          |

Шаблон:

```text
<type>(<KEY>-<number>): <short description in english, lowercase, why not what>
```

Примеры:

```text
fix(DENT-284): keep overlapping crown spans separate per tooth
feat(DENT-241): add desktop conversation list sidebar
fix(STO-170): align legal entity form validation with api errors
```

Правки после комментариев бота в PR — тот же шаблон, в описании можно уточнить контекст:

```text
fix(DENT-284): address cursor bot pr review comments
```

## 1. Первый коммит (только после апрува)

1. `git status`, `git diff` — убедись, что в коммит не попадают секреты и лишние файлы.
2. Сформулируй сообщение по таблице выше; покажи пользователю **текст коммита** и краткий список изменений.
3. **Не коммить**, пока пользователь явно не одобрил (например: «коммить», «ок», «апрув»).
4. После апрува:

```bash
git add <paths>
git commit -m "$(cat <<'EOF'
fix(DENT-284): short description

EOF
)"
```

5. Пуш — только по явной просьбе:

```bash
git push -u origin HEAD
```

PR пользователь открывает **вручную** в GitHub. CI запускается автоматически.

## 2. Комментарии бота в PR

Когда пользователь дал номер PR, ссылку или сказал «разбери комментарии бота»:

1. Прочитай контекст задачи (ТЗ из чата, тикета, описания PR) — это эталон.
2. Собери замечания через `gh` (не выдумывай):

```bash
gh pr view <number> --comments
gh api repos/{owner}/{repo}/pulls/<number>/comments
gh api repos/{owner}/{repo}/pulls/<number>/reviews
```

При необходимости: `gh pr checks <number>`.

3. Для **каждого** замечания вынеси вердикт:

| Статус | Когда |
|--------|--------|
| **исправлено** | Замечание валидно и не противоречит ТЗ — внеси правку в код |
| **не исправлено** | Осознанное решение по ТЗ/макету/API или замечание неверно — кратко обоснуй |
| **требует согласования** | Спор ТЗ vs бот, риск регрессии, неясный scope — остановись и спроси пользователя |

Не правь слепо всё под бота: если комментарий **противоречит ТЗ** или вы уже **сознательно** выбрали поведение из задачи — оставляем как есть, статус **не исправлено** с обоснованием.

4. Отчёт пользователю — таблица или список: файл/тема, цитата или суть бота, статус, что сделано.

5. После правок снова покажи сообщение коммита и жди **апрув** перед коммитом.

## 3. Squash в один коммит и force-with-lease

Делай только когда пользователь просит объединить коммиты в PR (или это явный шаг после правок по боту).

1. Убедись, что все нужные изменения закоммичены локально.
2. База — ветка PR (обычно `develop`):

```bash
git fetch origin develop
git merge-base HEAD origin/develop   # при необходимости проверить базу
```

3. Один коммит поверх `origin/develop` (пример):

```bash
git reset --soft origin/develop
git commit -m "$(cat <<'EOF'
fix(DENT-284): short description covering the whole pr

EOF
)"
```

Сообщение — итоговое по смыслу всего PR, тип и ключ из ветки.

4. Пуш:

```bash
git push --force-with-lease origin HEAD
```

**Не** используй `--force` без `--force-with-lease`. **Не** squash и не force-push без явного запроса пользователя.

## 4. Что не делать

- Не коммитить и не пушить без апрува (кроме шага squash, который сам по себе требует явного запроса).
- Не запускать отдельный Bugbot-навык для «авто-ревью» локально — здесь работаем с **комментариями уже оставленными в PR**.
- Не менять git config.
- Не amend после failed hook; не amend если коммит уже на remote, если пользователь не попросил иначе.

## Как вызвать

```text
tracker-commit-pr — апрув на коммит fix(DENT-284): ...
```

```text
tracker-commit-pr PR #42 — разбери комментарии бота по ТЗ DENT-284
```

```text
tracker-commit-pr — squash в один коммит и push --force-with-lease
```
